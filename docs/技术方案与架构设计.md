## 1. 设计目标与取舍

三条硬约束决定了整体架构：

1. **100 MB 文本必须秒开、翻页必须跟手** —— 决定了「绝不把整本塞进任何控件」，走 mmap + 切片分页。
2. **外观（字体/字号/行距/颜色）随时可调，且不丢阅读位置** —— 决定了进度基准必须是字节偏移，且改版式只重排当前页。
3. **本机无管理员权限、无 MSVC** —— 决定了不能走 Tauri/Rust，必须选一个能本地编译运行的栈。

### 为什么不用 `QPlainTextEdit` / `QTextBrowser`

它们的模型是「把全文交给一个控件」。100 MB 文本会让 Qt 为整本建立块结构，内存和排版开销都随文件线性增长，打开即卡死。

本项目的模型是「**控件永远只持有当前一页**」：一页约 400–1200 字，控件负担恒定，与文件大小无关。这是整个设计的支点。

## 2. 进程与线程模型

```
┌─────────────────────────────── 主线程（Qt GUI） ───────────────────────────────┐
│ QApplication                                                                   │
│   └ MainWindow（无边框）                                                        │
│       ├ TitleBar   自绘标题栏、拖动、最大化                                    │
│       ├ BookshelfView  书架卡片列表                                            │
│       ├ ReaderView     分页渲染 + 键盘输入                                     │
│       └ Tray       QSystemTrayIcon                                             │
│                                                                                │
│ 所有 QWidget / QTextDocument 操作只能在这里发生                                 │
└────────────────────────────────────────────────────────────────────────────────┘
                                    │ 信号 / 队列
┌───────────────────────────────────▼────────────────────────────────────────────┐
│ 后台工作线程（QThreadPool）                                                     │
│   • 行索引构建（>20 MB 时异步，100 MB 约 90 ms）                                │
│   • 全文搜索（100 MB 约 23 ms，命中多时流式回传）                                │
│   • EPUB 解压与转纯文本（M4）                                                   │
│   • 目录识别（M4）                                                              │
└────────────────────────────────────────────────────────────────────────────────┘
```

**为什么索引也要异步**：90 ms 虽短，但若在 `open_book` 里同步执行，加上解码与首屏排版，用户会看到一段空白。异步后首屏 82 ms 出内容，索引在后台补完，进度条提示「正在建立索引」。

**SQLite 访问策略**：单连接、主线程使用、WAL 模式。写入点很少（翻页节流 1 秒一次、退出时一次），不构成瓶颈；暂不引入连接池。若后续搜索历史/统计增多，再拆到独立线程。

## 4. 核心算法：切片分页

### 4.1 数据结构

```python
@dataclass
class Page:
    text: str      # 本页文本
    start: int     # 起始字节偏移（进度基准）
    end: int       # 结束字节偏移（下一页起点）
    chars: int     # 本页字符数
```

进度只存 `start`。它不随字体、字号、行距、窗口尺寸、编码切换而变——**这是「改字号不丢位置」能成立的唯一原因**。

### 4.2 排一页的流程

```
layout_page(start):
    start = align_offset(start)          # 跳过 UTF-8 续字节，避免页首方块
    window = 6 KB
    loop:
        text = mmap[start : start+window].decode
        cut  = capacity(text)            # 见下
        if 0 < cut < len(text):  break
        if cut >= len(text) and 还有更多文件: window *= 2; continue
        cut = max(1, cut)
    page_text = text[:cut]
    consumed  = len(page_text.encode())  # 字符数 → 字节数
    _apply(page_text)                    # 文档收敛成「正好这一页」
    return Page(page_text, start, start+consumed, len(page_text))

capacity(text):
    doc.setPlainText(text)
    给全文套 BlockFormat（行高）+ CharFormat（文字色）
    doc.documentLayout().documentSize()          # 强制排版
    pos = documentLayout().hitTest((内容宽/2, 内容高-1), FuzzyHit)
    跳过页尾换行符
    return pos
```

`hitTest` 返回「页底那条坐标线上是第几个字符」——这正是页边界，无需自己断行，中文标点禁则也由 Qt 负责。

### 4.3 复杂度与实测

| 操作 | 复杂度 | 100 MB 实测 |
| --- | --- | --- |
| 打开 + 首页 | O(页大小) | 82 ms（冷）/ 3.3 ms（热） |
| 下一页 | O(页大小) | 4.28 ms 均值 |
| 上一页 | O(1)（历史栈） | 同上 |
| 建行索引 | O(文件大小) | 87–108 ms / 288,250 行 / 2.2 MB |
| 全文搜索 | O(文件大小) | 23 ms（2 万命中） |
| 改字号重排一页 | O(页大小) | 12.9 ms |
| 内存 | O(1) | **77 MB 空载 / 80 MB 打开 100 MB 文档**（含 Qt 运行时） |

**关键结论**：翻页延迟与文件大小无关。100 MB 与 100 KB 的翻页速度一样；内存也与文件大小基本无关（打开 100 MB 只增加约 3 MB，因为走 mmap 未真读入）。

### 4.4 已知限制

| 限制 | 影响 | 计划 |
| --- | --- | --- |
| 页码是「本次阅读第几页」而非全书第几页 | 中途跳转后页码从 1 起算 | M2：抽样估算全书页数（按字符数/每页均值），给出近似页码 |
| 上一页无历史时靠估算回退 | 极端情况下会偏移半页 | M2：缓存最近 N 页起点，覆盖率足够 |
| 页边界可能落在段落中间 | 观感 | 可接受；分页阅读器的通行做法 |
| 竖排、双栏 | 不支持 | 明确不做（PRD §4 FR-4.10） |

## 5. 关键数据流

### 5.1 打开文档

```
书架点击书卡
  → Library.get_book(id)               取路径与记住的编码
  → TextFile.open()                    mmap + 采样判编码（无 BOM 时）
  → Library.get_progress(id)           取上次字节偏移
  → ReaderView._rebuild_paginator()    按当前设置造 Layout
  → Paginator.layout_page(offset)      排首页（offset 先 align）
  → stack.setCurrentWidget(reader)     切到阅读视图
  → 索引异步构建（完成后目录/搜索可用）
```

### 5.2 翻页

```
按 E
  → MainWindow.keyPressEvent           先查 focusWidget 是否输入框
  → ReaderView.next_page()
  → pg.layout_page(page.end)           一次切片 + 一次排版
  → update() → paintEvent → doc.drawContents()   零额外排版
  → save_progress()（1 秒节流）
```

### 5.3 改外观

```
设置面板改动
  → Settings.set(...) + save()
  → MainWindow.setStyleSheet(build_qss(settings))   重刷 QSS
  → ReaderView.apply_appearance()
       offset = page.start          ← 记住位置
       _rebuild_paginator()         ← 新 Layout
       layout_page(offset)          ← 从同一字节偏移重排
```

位置不变、页码可能变，这正是验收项 AC-5 要验的行为。

## 6. 界面状态机

```
                 ┌──────────┐
   启动 ────────►│  书架页   │◄──────── Ctrl+W / 关闭文档
                 └────┬─────┘
                      │ 点击书卡 / Ctrl+O 后选中
                 ┌────▼─────┐
                 │  阅读页   │  Q / ← / PgUp   → 上一页
                 │           │  E / → / PgDn   → 下一页
                 └────┬─────┘  Ctrl+±        → 字号
                      │ ESC / ✕ / 最小化
                 ┌────▼─────┐
                 │  托盘态   │  双击托盘 / 菜单「显示主窗口」
                 └────┬─────┘
                      │ 菜单「退出」
                   进程结束（进度已落盘）
```

`ESC` 的三个去处必须按优先级仲裁，否则会互相踩：

| 优先级 | 场景 | `ESC` 行为 |
| --- | --- | --- |
| 1 | 焦点在输入框（搜索、重命名） | 取消输入并失焦 |
| 2 | 模态浮层打开（取色遮罩、确认框） | 关闭浮层 |
| 3 | 正文聚焦 | 最小化到托盘 |

| 套件 | 内容 |
| --- | --- |
| `smoke_core` | 18 项：编码识别、mmap 索引、页边界连续性、改字号重排、书架存储、设置持久化 |

## 9. 踩坑记录（都是实测踩出来的）

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 内存 542 MB，首帧就涨 470 MB | 标题栏按钮用 `✕`/`▢` 字符做图标，Qt/DirectWrite 为找字形**枚举了整个字体库** | 改用 QPainter 矢量绘制，内存降到 77 MB |
| UTF-8 语料被判成 UTF-16 | 任意 UTF-8 中文字节流按 `utf-16-le` 解码几乎总落在汉字区，纯按「汉字占比」打分会误判 | 调整顺序：BOM → NUL 占比 → **UTF-8 增量解码自校验** → 再试传统编码 |
| UTF-8 置信度只有 0.30 | 256 KB 采样切断多字节字符，严解码直接抛异常 | 用增量解码器 `final=False` 容忍截断；采样头部与中部两块投票 |
| 跳到中途页首出现「方块」替换符 | 字节偏移落在 UTF-8 多字节字符中间（4 个随机偏移有 3 个中招） | `align_offset()` 跳过续字节（`b & 0xC0 == 0x80`） |
| 页脚与正文栏不齐 | 页脚按整窗宽度对齐 | 页脚也按正文栏的 `col_x` 与栏宽绘制 |
| 中文两端对齐出现难看字间隙 | 行内剩余空间被均摊到字间 | 默认改左对齐，两端对齐降为可选项 |
| `danger-full-access` 下创建的目录后续读不了 | 该模式创建的对象 ACL 与普通沙箱身份不匹配 | 装依赖改为「Node 下载 wheel + `zipfile` 解压」，全程只写不删 |
| 拖窗口宽度后正文变白，翻页才恢复 | `resizeEvent` 先无条件重建 Paginator（新文档是空的），再判断「版式变了才重排」；正文栏被 `maxContentWidth` 卡住时签名不变 → 空白文档 | 先算候选版式比较签名，只在不同时才重建，并把「重建 + 重排」合并成 `_apply_layout()` 原子操作；新增 `test_reader` 断言检查 `pg.doc` 实际内容而非 `page.text` 缓存 |
| 目录识别要 2.3 秒 | 在 `toc.py` 里逐行调 `line_start()`/`read_bytes()`，28.8 万行 × 每次方法调用 | 下沉到 `TextFile.short_lines()`，循环内只做数组索引 + mmap 切片 → **65 ms**（35×） |
| 搜索跳转后页面从半句话开始 | 直接从命中偏移开头，把行切断了 | `goto_offset(align_line=True)` 回退到所在行行首（仅当行内偏移 ≤ 400 字节，避免命中被推出页外） |
